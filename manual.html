0. Que es el Servidor Web de Franky?
🌐 Servidor HTTP embebido en el ESP32-C3

El ESP32-C3 corre un servidor web real dentro del microcontrolador. No necesita internet, nube, ni computadora intermediaria. El robot es el servidor: genera y entrega todas las paginas desde su memoria interna (SPIFFS).

Cuando conectas el celular a la red Wi-Fi Franky_4.0 y abres http://192.168.4.1, tu navegador esta hablando directamente con el chip del robot.

Como funciona (sin magia)

  • El ESP32-C3 crea una red Wi-Fi propia (modo Access Point — sin router externo).
  • Cualquier dispositivo que se conecte a esa red queda en la misma subred 192.168.4.x.
  • El firmware escucha en el puerto 80 (HTTP estandar) y responde a solicitudes del navegador.
  • Los archivos HTML, CSS y JS se guardan en la particion SPIFFS del chip y se sirven como si fuera un hosting clasico.
  • Los comandos (mover, leer sensores, ejecutar programas) llegan como peticiones HTTP GET sencillas: /mv?d=f, /api, etc.

Por que HTTP y no HTTPS?

El cifrado SSL/TLS requiere mucha memoria RAM y poder de computo. El ESP32-C3 tiene 400 KB de RAM — suficiente para el servidor, los motores y los sensores, pero no para una pila TLS completa. Ademas, en una red local privada sin datos sensibles, HTTP es completamente adecuado.

💡 Dato importante: Chrome bloquea el acceso a la camara del navegador en sitios HTTP (no HTTPS). Por eso el modulo de camara no se incluye en esta version.

Ventajas para educacion

  • Sin dependencias externas: funciona en un aula sin internet, con cualquier celular o computadora.
  • Interfaz grafica accesible: cualquier alumno puede controlar el robot desde su dispositivo sin instalar nada.
  • API REST visible: los alumnos pueden ver exactamente que comandos se envian al robot, ideal para aprender redes y protocolos.
  • Programacion sin cable: el editor de bloques corre en el navegador y envía el programa al robot por Wi-Fi.
  • Multidispositivo: varios celulares pueden conectarse a la vez (solo uno controla los motores a la vez por seguridad).
  • Transparencia tecnica: se puede inspeccionar el trafico HTTP con herramientas del navegador, excelente para materias de redes.
1. Conexion Wi-Fi

Como conectarse

  • Energizar la placa con bateria LiPo 2S (7.4V) o USB-C.
  • En el dispositivo buscar la red Wi-Fi y conectarse:
SSID: Franky_4.0 Password: 12345678 IP: 192.168.4.1
  • Abrir el navegador y escribir exactamente: http://192.168.4.1
  • Importante: escribir http:// (no https). Usar Firefox si Chrome no abre.

Estructura de paginas

  • / — Menu principal con estado del sistema
  • /gamepad.html — Control manual con D-pad y joystick

  • /bloques.html — Editor de programacion con bloques
  • /auto.html — Automatizaciones predefinidas
  • /panel.html — Panel industrial con monitores y sensores
  • /manual.html — Este manual

3. Gamepad — Control Manual

Modos de control

  • D-PAD: Cuatro botones de direccion. Mantener presionado = movimiento continuo. Soltar = frena.
  • Joystick virtual: Arrastrarlo en cualquier direccion. Suelta el dedo = para el robot.
  • Turbo: Boton adelante a velocidad maxima (255 PWM = 20 kHz).

Slider de velocidad

Controla el duty cycle del PWM (0-255). Al 100% la frecuencia es 20 kHz — inaudible. Recomendado: 60-80% para maniobras de precision.

Ejemplo de uso educativo

  • Conectar el robot y moverlo con el D-pad.
  • Observar en el Panel Industrial los valores ADC mientras el robot avanza.
  • Colocar la mano frente al sensor IR y ver como cambia el ADC0.
4. Panel Industrial

Monitor de entradas analogicas

Muestra ADC0 (GPIO0) y ADC1 (GPIO1) en tiempo real con barra de progreso. Rango 0-4095 (0V-3.3V).

Monitor de entradas digitales

Muestra el estado (0/1) de GPIO9 (pulsador Start) y los pines de buses cuando estan deshabilitados. Los pines del motor no se pueden leer.

Sensor ultrasonico HC-SR04

  • Elegir pines TRIG y ECHO del dropdown (solo pines disponibles segun buses).
  • Activar con el boton. Muestra distancia en cm y barra visual.
  • Requiere NewPing instalada en Arduino IDE.

Conexion HC-SR04

HC-SR04 → Franky 4.0 VCC → 3.3V (o 5V si se usa divisor de tension en ECHO) GND → GND TRIG → GPIO20 (SPI off) o GPIO6 (I2C off) ECHO → GPIO21 (SPI off) o GPIO7 (I2C off) Nota: si se usa 5V en VCC, poner divisor resistivo en ECHO ECHO → R1(1kΩ) → GPIO → R2(2kΩ) → GND

Sensor DHT22 — temperatura y humedad

DHT22 → Franky 4.0 VCC → 3.3V GND → GND DATA → GPIO3 (compilado, 1-Wire) + resistencia 10kΩ entre DATA y 3.3V (pull-up)

LED y brillo

GPIO8 usa logica invertida. El slider de brillo ajusta el PWM automaticamente (0%=apagado, 100%=maximo brillo).

5. Modo Sumo LNR

Microsumo — configuracion de sensores

El ESP32-C3 solo tiene 2 entradas analogicas (ADC0 y ADC1). Para microsumo ambas son analogicas:

  • ADC0 (GPIO0): Sensor de distancia frontal — detecta al oponente. Tipicamente un sensor IR como GP2Y0A21 o TCRT5000.
  • ADC1 (GPIO1): Sensor de borde del dojo — detecta la linea blanca. TCRT5000 en modo analogico.

Calibracion de umbrales

  • Abrir el Panel Industrial para ver los valores ADC en tiempo real.
  • Poner el robot en el dojo y anotar el valor cuando el sensor esta sobre el negro.
  • Poner el sensor sobre la linea blanca y anotar ese valor.
  • El umbral de borde debe estar entre esos dos valores.
Ejemplo tipico TCRT5000 en modo analogico: Sobre negro (dojo): ADC ~300-800 Sobre blanco (borde): ADC ~2500-3500 → Umbral borde recomendado: 1500

Minisumo — sensores digitales de borde

Para minisumo con 4 sensores: los 2 ADC van para distancia y los sensores de borde deben tener salida digital. Usar TCRT5000 + LM393 (comparador) o modulos con potenciometro de calibracion integrado.

Inicio y combate

  • Presionar INICIAR en la pagina Sumo.
  • El LED parpadea durante 5 segundos (reglamento LNR).
  • Al terminar el conteo el robot arranca automaticamente.
  • Para detener: presionar DETENER en la pagina (el robot sigue el reglamento de no-conexion externa durante el combate).
6. Programacion con Bloques

Requisito: internet la primera vez

Blockly se carga desde internet (unpkg.com). La primera vez que abres /bloques.html el celular necesita tener datos moviles o Wi-Fi a internet activos. Despues queda en cache del navegador.

Categorias de bloques

  • Motores (naranja): adelante, atras, giro, freno, PWM directo por canal
  • Servo: mover a angulo, barrido entre dos angulos
  • GPIO/Salidas: digital HIGH/LOW, PWM configurable, LED
  • Sensores: leer ADC, digital, ultrasonico, DHT22
  • PID *: configurar Kp/Ki/Kd, iniciar, detener (solo codigo C++)
  • OLED I2C *: texto, numeros, formas (solo codigo C++)
  • Decision: si sensor mayor/menor/igual, comparaciones, AND/OR
  • Control: repetir N veces, mientras sensor, for, while
  • Variables: asignar, incrementar, decrementar
  • Matematicas: map(), constrain(), operaciones
  • Tiempo: esperar ms, esperar us, leer millis()
  • Serial: imprimir texto y valores para debug

* Bloques marcados con * generan solo codigo C++ (requieren librerias adicionales). Se pueden ver en la pestana "Codigo C++" pero no ejecutan en el interprete del ESP32.

Botones del editor: Ejemplos y Guardar XML

⚠ Los botones Ej: Va y vuelve, Ej: Evasion y XML solo funcionan correctamente cuando Blockly termino de cargar. Si se hace clic antes de que la barra de progreso desaparezca, el boton no hara nada. Esperar a que aparezca el area de bloques.
  • Ej: Va y vuelve — Carga en el workspace el programa de ejemplo basico: adelante 500ms, atras 500ms, repite. Util como punto de partida para principiantes.
  • Ej: Evasion — Carga el programa de evasion de obstaculos: si ADC0 supera 2500 gira a la derecha, si no avanza. Sirve para demostrar sensores y logica condicional.
  • 💾 XML — Descarga el programa actual del workspace como archivo franky_programa.xml en tu dispositivo. El XML es el formato nativo de Blockly: guarda la estructura exacta de los bloques (posicion, tipo, valores) para poder recargarla despues.

Para que sirve guardar en XML?

  • Persistencia: el workspace de Blockly no se guarda automaticamente en el ESP32. Si cierras el navegador, el programa se pierde. El XML es el respaldo.
  • Compartir entre alumnos: un alumno puede guardar su programa, enviarlo por mensaje o correo, y otro alumno puede cargarlo en su propio Franky.
  • Iteracion pedagogica: guardar versiones distintas del mismo programa (v1, v2, v3) y comparar como evolucionan.
  • Archivo de trabajos: el docente puede coleccionar los XML de todos los alumnos como entregable de la actividad.
💡 Para recargar un XML guardado: proximamente se agregara el boton Cargar XML. Por ahora, abrir el archivo .xml con un editor de texto, copiar el contenido, y pegarlo en la consola del navegador con Blockly.Xml.clearWorkspaceAndLoadFromXml(...).
7. Ejemplos de Programas en Bloques

Ejemplo 1 — Va y vuelve (basico)

El robot avanza 500ms, retrocede 500ms, y repite.
Adelante 200→ Esperar 500ms→ Atras 200→ Esperar 500ms→ Parar→ FIN (repite)

Ejemplo 2 — Evasion de obstaculos

Si detecta objeto cerca (ADC0 alto), gira; si no, avanza.
Si ADC0 > 2500→ Girar derecha 180→ Esperar 300ms
Adelante 180→ Esperar 100ms→ FIN (repite)
// Codigo C++ equivalente: void loop() { if(analogRead(PIN_ADC0) > 2500) { move("r", 180); delay(300); } move("f", 180); delay(100); }

Ejemplo 3 — Control de LED con sensor

El LED se enciende cuando hay un objeto frente al robot.
Si ADC0 > 2000→ LED Encender
Si ADC0 < 2000→ LED Apagar→ Esperar 50ms→ FIN

Ejemplo 4 — Zigzag temporizado

El robot hace un zigzag 5 veces.
Repetir 5 veces:
  Adelante 200→ Esperar 400ms→ Girar izquierda 200→ Esperar 200ms→ Adelante 200→ Esperar 400ms→ Girar derecha 200→ Esperar 200ms
Parar

Ejemplo 5 — Seguidor de linea basico

ADC0 es sensor de linea. Valor bajo = linea negra, alto = blanco.
Mientras ADC0 < 1000→ (sobre linea negra)
  Adelante 150→ Esperar 20ms
Si ADC0 > 1000→ (salio de la linea)
  Girar derecha 160→ Esperar 100ms→ FIN

Ejemplo 6 — Variable acumuladora

Contar cuantas veces el sensor detecta algo y parpadear el LED.
Variable contador = 0
Si ADC0 > 2500→ contador += 1→ LED Encender→ Esperar 200ms→ LED Apagar
Esperar 100ms→ FIN

Ejemplo 7 — Servo como barrera

Servo en GPIO3. Se abre cuando detecta proximidad, se cierra si no.
Si ADC0 > 2000
  Servo GPIO3 → 90°→ Esperar 2000ms→ Servo GPIO3 → 0°
Esperar 100ms→ FIN

Requiere ESP32_Servo instalada (ver seccion Librerias). El bloque Servo genera codigo C++ — ver pestana Codigo C++ para el sketch completo.

Ejemplo 8 — Mapa de sensor a velocidad

La velocidad del motor varia segun la distancia al obstaculo.
Variable vel = map(ADC0, 0, 4095, 50, 255)
Adelante [vel]→ Esperar 50ms→ FIN
// Codigo C++ equivalente: void loop() { int vel = map(analogRead(PIN_ADC0), 0, 4095, 50, 255); vel = constrain(vel, 50, 255); move("f", vel); delay(50); }
8. API REST — Integracion Externa
GET /api — Todos los datos en JSON GET /mv?d=f — Adelante GET /mv?d=b — Atras GET /mv?d=l — Izquierda GET /mv?d=r — Derecha GET /st — Parar motores GET /spd?val=200 — Velocidad PWM (0-255) GET /led/on — LED encender GET /led/off — LED apagar GET /led/brillo?val=N — Brillo (0=max, 255=apagado) GET /gpio/out?pin=N&val=V — Salida digital GET /sonar/read?trig=N&echo=M — Leer ultrasonico GET /stopall — Parar todo + modo IDLE

Respuesta /api (JSON)

{ "a0": 1234, // ADC0 (0-4095) "a1": 567, // ADC1 (0-4095) "btn": 1, // GPIO9 Start (1=libre, 0=presionado) "temp": 23.50, // Temperatura DHT22 (C) "hum": 65.20, // Humedad DHT22 (%) "mode": 0, // Modo: 0=IDLE 1=MICRO 2=MINI... "running": 0, // Programa corriendo (0/1) "proglen": 5, // Instrucciones en NVS "i2c": 0, // I2C habilitado (0/1) "spi": 0, // SPI habilitado (0/1) "dht": 1 // DHT22 OK (0/1) }

Ejemplo Python

import requests, time IP = "http://192.168.4.1" # Mover robot adelante 1 segundo requests.get(f"{IP}/mv?d=f") time.sleep(1) requests.get(f"{IP}/st") # Leer sensores datos = requests.get(f"{IP}/api").json() print(f"ADC0: {datos['a0']} Temp: {datos['temp']} C")

Ejemplo JavaScript (desde celular)

// Control desde pagina web externa fetch("http://192.168.4.1/mv?d=f") .then(() => setTimeout(() => fetch("http://192.168.4.1/st"), 1000)); // Leer datos en tiempo real setInterval(() => { fetch("http://192.168.4.1/api") .then(r => r.json()) .then(d => console.log("ADC0:", d.a0, "Temp:", d.temp)); }, 500);
9. Automatizaciones

Vivero automatizado

  • Sensor DHT22 en GPIO3 (1-Wire, 10kΩ pull-up a 3.3V).
  • Salida de riego: conectar rele en GPIO9 o GPIO libre. El rele activa una bomba o valvula.
  • Logica: si humedad < 50% → activa riego. Ajustable en el firmware.
// Conexion DHT22 DHT22 VCC → 3.3V DHT22 GND → GND DHT22 DATA → GPIO3 + 10kΩ entre DATA y 3.3V

Estacion meteorologica

  • DHT22 para temperatura y humedad (igual al vivero).
  • BMP280 para presion: conectar por I2C (GPIO6 SDA, GPIO7 SCL). Habilitar I2C en Panel.
  • Los datos se muestran en /auto.html y se leen por /api.

Sistema de alarma

  • Sensor PIR en GPIO0 (ADC0). Salida analogica: valor alto = movimiento.
  • Umbral de deteccion: ADC0 > 2000 = movimiento detectado.
  • LED GPIO8 se enciende como indicador. Agregar buzzer en GPIO libre si se desea sonido.

Control de acceso

  • Pulsador Start (GPIO9) como sensor de activacion.
  • Servo en GPIO3 como cerradura electronica (0° = cerrado, 90° = abierto).
  • Para RFID: modulo RC522 por SPI (GPIO1/10/20/21). Requiere SPI habilitado.
